## Summary

Feature 12 and its four reviews left a family of misses in spec 0005: a neighbour's digit group, or a footnote marker glued to a value, hides the value or gives it the wrong row. This spec settles them in one pass. The phone detector learns to rescue a digit group it would otherwise strand beside a number (today `9346 212 555 0123` lists `9346 212 555` and leaves `0123` in the file with no row). It runs after every number today's detector chooses and lists each rescued group as a row of its own, unticked, so every row listed today keeps exactly its end and its tick, the default never removes less than today, and a rescue never takes a digit another row would have had; a group that also begins a date stays with the date. The find step learns that a small glyph raised or lowered off its line (a superscript, a subscript, an ordinal's letters) is not part of the text a detector reads, so a footnote marker can never glue to a value of any kind, and a row can never hold one, which today refuses the whole run. The one digit text rules feature 12 added stay for text that was read by OCR (optical character recognition, where a marker comes back as a plain digit), and gain the three cases the fourth review measured. Everything was measured on real MuPDF, on a page printed by Chromium, and on every string the detector tests and fixtures hold (1,258 of them) before it was chosen; the figures are in `rationale.md`.

## Requirements

**User stories**:
- As a visitor reviewing a document, I want every digit of a phone number that has digit groups beside it listed in a row, with every row ticked today still ticked, so that no digit of it is left with no row next to a row that looks complete, and the default never removes less than it does today.
- As a visitor, I want a value followed by a footnote marker listed and removable whatever its kind and however the marker is drawn, so that a reference mark never hides an email address or a phone number, and ticking the row never fails the run.
- As the maintainer, I want the premise that MuPDF reads a raised marker as glued held by a test on a real raised glyph, so that an engine upgrade cannot quietly bring the miss back.

A free unit is one neither pass took. The valid pass visits every unit outside a row it chose, so no free unit starts a valid window, and every valid window that covers a free unit starts inside a row the valid pass chose. ## Decision

**Chosen option**: rescue stranded units in the phone chooser, each rescued stretch listed as a row of its own (not a merge of every overlapping window, and not a join into the row beside it), an off line boundary in the find step by geometry and by code point with each short glued stretch read as a synthetic space and the target quads parted round it, and the text tolerances kept and extended by the three measured cases (reasoning and the other options in `rationale.md`).

- **The rescue, not the merge, and each stretch a row of its own.** Merging every overlapping valid window, the card's rule, fixes the leak but glues 60% of random US numbers side by side into one unticked row, because a window across two numbers' middles is valid by chance. Rescuing only a unit that would otherwise be stranded keeps every pair apart and loses no digit anywhere today keeps one. Each rescued stretch is listed as its own unticked row, not joined into the row beside it: a joined row had to be unticked, since it may hold a neighbour's digits, so it removed less by default than today's ticked row (`9346 212 555 0123` from seven digits to none, and up to 40.9% of a layout's numbers), and the owner's bar is that the default never removes less than today. As its own row the stretch lists every digit the joined row listed, every row today lists keeps its exact end and tick, and the default removes at least what it removes today in every string measured. Its cost is rows: a number cut by a stray group before it reads as two, the first ticked as today and the stretch unticked, and a stray group after a UK number lists as an extra unticked row about 12% of the time; the owner's rule, extra unticked rows are fine and missed values are not, accepts that. The runner up, a rescue only by a window at least as long as the row's own number, rescues less (12.4% of US numbers with three groups before still leak, 5.8% with the chosen rule) and, with stretch rows, saves no tick, since no rescue now changes one. The rescue runs last, after both of today's passes, so it only ever gives a row to a unit today's chooser leaves with no row, and no digit today's chooser keeps can be lost to it; run before the possible pass, as first drafted, it took `020` from `020 2977 5777` and left `2977 5777` in the file, and lost more digits than today on UK numbers side by side. Its lookup is skipped where no free unit is in reach, which changes no result and keeps numbers side by side at today's cost. And because phone outranks date, a rescued stretch yields to a date in `detect` (AC-15): the phone detector cannot see where the date detector reads a date, and a guard inside it (no rescue before a letter or a slash) would also stop the rescue of a number followed by a word, the commonest case in prose.
- **Geometry and code point, read as a join.** MuPDF keeps a raised glyph on its line, glued up to a 1 pt gap, and reports its rise and size exactly, so a glyph both smaller than its line and shifted off its baseline is a marker with no grammar to maintain. Size alone would drop small print on the same baseline (8 pt text inside 12 pt), and shift alone would wobble on OCR layers; both together flagged none of 78,856 real glyphs and none of a Chromium printed table with a 9 pt cell aligned middle. The size cap is 0.9 because Chromium's default superscript prints at 0.83, and the shift floor 0.15 because that cell sits at 0.06 while every superscript measured sits at 0.23 or more. A full size `¹` glyph has no geometry and only its code point, so the code point set is the second trigger. A short glued run reads as one synthetic space, none beside whitespace, because that is the one reading under which `27ᵗʰ September 2026` reads `27 September 2026` and `1980¹on` reads `1980 on`; dropping it with no space glues the next word, and keeping it as text breaks ordinals. The gluing rule and the cap keep a spaced value or an isolated word drawn small and shifted in the text. The target quads are parted round an off line stretch inside a span, because a line quad spanning the kept characters would still contain the raised letters of `27ᵗʰ` and target validation would then block the row as unsound.
- **Tolerances kept.** A boundary cannot see a marker that OCR returned as a plain digit on the baseline, and the fixtures draw exactly that. The three new tolerances take the fourth review's measured shapes; the bare Social Security one costs what the separated one already does.
- **Masking deferred.** Running lower kinds with a higher kind's positions read as spaces would list `020 7946 0958` after a card as one ticked row, where this spec lists today's ticked piece `020` and the stretch `7946 0958` unticked, and settle the card then date case; it changes how `detect` runs every kind and needs its own measurement, so it stays recorded under Follow-up.

**Implementation skills**: none; this is detector and engine code under the project's own rules.

## Feature design

**Data model sketch** (in memory only, nothing stored or sent):
- `Character` (spec 0005) is unchanged: `quad`, `origin` and `direction` already carry what AC-4 reads. `walkCharacters` still discards the size MuPDF reports, because the quad height is the same signal and is what the self check reads (spec 0004, `LINE_HEIGHT_MIN`).
- `pageText` in `src/engine/find.ts` buffers each line's characters before it writes them (lines are contiguous in extraction order), computes the dominant height and baseline, marks each glyph off line by AC-4 or AC-5, finds the runs, and writes each run that leaves as one synthetic space with `source` of -1, not listed in `joins`; a run that stays is written as ordinary characters. `PageText` and `BlockText` keep their shape, and each `Character` the page keeps is mapped as today. The find step keeps, per read, which characters are off line (a `Uint8Array` over `characters`), which `lineQuads` reads to part a span's quads (AC-7).
- `Window` in `src/detect/phone.ts` gains one optional field, `rescued: true`, set only on a stretch's row. The chooser keeps, across both passes and the rescue, an `owner` array (a `Uint32Array` over the run's units: the row each unit belongs to, counted from 1 in the order chosen, so 0 is a free unit), with `validRows` the count of rows when the valid pass ends, and a `rescued` array (a `Uint8Array` over the run's units). The rescue sets `rescued[index]` for each free unit a window covers and changes nothing else. The sweep then adds one `Window` per stretch, `{ start: run[first].start, end: run[last - 1].end, last, reading, valid: false, rescued: true }`, with `reading` as AC-2 names it. Every window the two passes chose is returned as its own object, untouched, and the list is sorted by `start`. The possible pass's `freeUntil` reads `owner`, so it is built after the valid pass as today. *Detectors* step 7 reads an extension after each returned window's `end`, a stretch's included. `keeps` gives every row today's answer: a row with another unit after it in its run is followed by whitespace and a digit, which no marker matches, so it has no extension; and a stretch is never a run's first unit, so it never starts inside an extension's digits, which open the next run (`212 555 0123 ext. 4567 212 555 0124` is unchanged). No measurement switch (the prototype's `SKIP`) ships.
- `Span` in `src/detect/types.ts` gains one optional field, `rescued: true`, which `detectPhone` sets on a stretch's span and `detect` reads and strips (AC-15). No other detector sets it.
- `Unit.date` is set by AC-3's first rule as well as `isNumericDate`; the second rule acts in `unitAt`, where a hyphen glues the next group.
- Engine constants, beside `LINE_HEIGHT_MIN` in `src/engine`: `OFF_LINE_SIZE_MAX = 0.9`, `OFF_LINE_SHIFT_MIN = 0.15`, `OFF_LINE_STRETCH_MAX = 4`, `OFF_LINE_MIN_LINE_GLYPHS = 3`, `SUPERSCRIPT_CODE_POINTS` (a frozen `Set` built from the ranges AC-5 names). Detector constants in `src/detect`: none new; the tolerances are rules in `date.ts`, `us-ssn.ts` and `uk-nino.ts`.

**Key invariants**:
- **INV-1**: The rescue only adds rows. It runs after both choosing passes and lists only units both left free, each stretch as a row of its own, so every row today's chooser lists is still listed with exactly its start, end, units and tick, and no digit today's chooser puts in a row loses it. No digit a valid phone window covers is left without a row because another window was chosen: a unit a valid window covers either lies in a row or is rescued (AC-1), since every shorter valid window from a start covers a part of the longest one. A stretch never holds a unit another row holds, so INV-13's "no unit belongs to two matches" still holds.
- **INV-2**: A stretch's row is never ticked, and no row the two passes chose loses its tick (AC-2), so the digits ticked by default are always a superset of today's: the default never removes less than it removes today, and the rescue never removes a neighbour's digits by default.
- **INV-7**: The rescue never takes a position another kind's row holds today. Through `detect`, every position any of today's rows holds is still held by a row of the same kind, and every ticked row of today's, of any kind, keeps its tick: the rescue adds only rows over units today's chooser leaves free, and a stretch yields to every kind below `phone` (AC-15), so every lower kind's span resolves exactly as today.
- **INV-3**: A glyph off its line, by geometry or by code point, is never part of a span, a target's text or a target quad (AC-4, AC-5, AC-7), so no detector meets a real raised marker, the self check never meets one inside a ticked row, and removal never reaches one.
- **INV-4**: The boundary only removes positions from the page text; it never adds a character and never widens the text a span can cover. A run longer than `OFF_LINE_STRETCH_MAX` solid glyphs, or one not glued to a kept glyph, stays, so a spaced value or an isolated word drawn small and shifted is never dropped from detection.
- **INV-5**: A text tolerance drops nothing: it can only list a value that a glued digit hid, with the digit outside its row (spec 0005, INV-17).
- **INV-6**: Every rule here is measured before it lands, and the figures live in `rationale.md`; a rule whose cost on random codes is not recorded is not built.

The constants are rules about pages, not caps on the visitor, so they live in `src/engine` and `src/detect` where no environment variable can switch a check off (spec 0004, spec 0005, spec 0006, INV-7).

## Consequences

**Positive**:
- A phone number beside a stray digit group is far less often cut to leave part of itself with no row: one random group before a US number left digits with no row 36% of the time, three groups 45%; after the rescue 1.6% and 5.8% on the first round's layouts (0.0% and 0.0% on the build's), and the UK number after a spaced card has a row for every digit. Because the rescue runs last, no string loses a digit today's chooser keeps in a row (0 of 40,000 random strings), and UK numbers side by side lose fewer digits than today (2.9% against 4.1% on the first round's layouts, 4.6% against 5.6% on the build's).
- The default never removes less than today. Every row today lists keeps exactly its end and its tick, and the digits ticked by default are a superset of today's in every string measured: 0 of 40,000 random strings, phone alone and through `detect`, 0 of 60,000 beside dates, and 0.0% in every cell of both rounds' layouts, where the joined row of 2026-10-15 removed less than today in up to 40.9% of a layout's numbers.
- Because a rescued stretch yields to a date, a date beside a number keeps every digit it has today: 0 of 60,000 strings putting numbers, stray groups and dates side by side lose a position of any of today's rows, and none loses a tick.
- A footnote marker drawn the way word processors, typesetters and browsers draw one can no longer hide an email address, a phone number, a date with a two digit year, a bare Social Security number or a National Insurance number, and no row ever holds or covers the marker, so ticking a marked value never refuses the run. On the Chromium printed page in `rationale.md`, six of the eleven marked values give no row today.
- The boundary is one rule in one place for every kind, present and future, with no grammar to extend; the per kind text tolerances stay only for text that has no geometry.
- A real raised marker through MuPDF is held by a committed fixture and a test, so an engine upgrade that reads raised glyphs differently fails a test instead of bringing the miss back in silence.
- The INV-14 unit rules close the last two layouts where a numeric date reached a phone row, and the ISO interval's second date lists under Dates.

**Negative / tradeoffs**:
- A rescued group is a row of its own, unticked, so by default it stays in the file, as it does today; the visitor ticks it. A number cut by a stray group before it reads as two rows: `9346 212 555 0123` lists `9346 212 555`, ticked as today (the stray group and seven of the number's ten digits), and `0123`, unticked. And a stray group after a number lists as an extra unticked row: after a UK number about 12% of the time on the first round's layouts (10.9% to 12.8% by layout; a `+44` number 6.6% to 7.2%) and about 9% on the build's (5.8% to 11.7%), because an 8 digit window such as `0958 1234` is valid under the GB metadata, and after a US number 0.3% with two groups after (0.2% on the build's). Measured on 3,000 random layouts per shape.
- A number followed by digits the date detector does not read as a date, such as the spaced `16 07 1995`, lists the first group as an extra unticked row, as a stray group does: 0.40% of strings where a number is followed by a date in some form. And `detect` gains one step and `Span` one optional field (AC-15), which only `src/detect` sees.
- A stretch can hold the next number's first digits when today's chooser leaves them with no row: `212 526 5087 020 2208 1633 24` lists `020` as an unticked row between two ticked ones, where today `020` stays in the file with no row, so that number reads as two rows.
