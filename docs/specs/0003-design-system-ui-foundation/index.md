## Summary

RedactNest gets one small, calm visual language: a warm off white page, a soft teal accent, rounded cards and Inter for every piece of text. It is built from a fixed set of named colour tokens whose contrast a test checks, plus about a dozen React primitives in `src/ui/` that wrap native HTML elements, so keyboard and screen reader behaviour come from the browser rather than from our code. The existing tool page and the placeholder home page are restyled with them, which is where WCAG 2.2 AA (the accessibility standard this product commits to) is proved in a real browser. Features 6, 7, 8 and 15 then compose these pieces instead of inventing their own.

## Requirements

**Design source**: the four screenshots in `docs/design/references/`, used for visual style only (colour direction, spacing, type feel, component shapes). Their layouts, logos, navigation items, copy and claims are not used. They were generated by an image tool, so every colour below was adjusted and measured for contrast rather than sampled.

- `01-tool-review.png`: warm off white background, soft teal accent, teal highlight on matched text, rounded cards with count badges, the checkbox style, calm spacing.
- `02-upload-empty.png`: the dashed drop zone, an icon in a soft teal circle, the empty state pattern (muted icon, short title, one helper line).
- `03-warnings.png`: the amber warning card, the light blue info card, the outlined secondary button beside the solid teal primary, collapsible groups with count badges and right aligned page numbers.
- `04-landing-hero.png`: the large bold display headline, the small letter spaced eyebrow label, the feature trio with teal line icons, the header button style.

**User stories**:

- As someone redacting a document with only a keyboard or a screen reader, I want every control reachable, named and visibly focused, so I can do the whole job without a mouse.
- As someone with low vision, or using Windows High Contrast, I want text, controls and the focus ring to stay legible, so I never lose track of what I am about to remove.
- As someone reviewing what was found, I want each match shown with its page and its surrounding text highlighted, so I can judge it before I tick it.
- As the engineer building features 6, 7, 8 and 15, I want the tokens and pieces already decided and tested, so I compose rather than invent, and cannot introduce a colour nobody has checked.

**Acceptance criteria** (the contract):

- **AC-1**: The colour tokens in the Token table are the only colours available. Tailwind's default palette is removed (`--color-*: initial`), each token is defined once in `src/app/globals.css`, and the page declares `color-scheme: light`. There is no dark theme.
- **AC-2**: Every pair in the Contrast contract meets its minimum (4.5:1 for text, 3:1 for icons, control edges and the focus ring). A unit test reads the token values from `globals.css` and checks every pair, so changing a token until a pair fails makes the test fail.
- **AC-3**: Lint rejects an arbitrary colour value in a class name (`bg-[#1a2b3c]`, `text-[rgb(...)]` and the other colour functions) and an alpha modifier on a colour utility (`text-ink/70`, `border-current/40`) anywhere under `src/`, using the two patterns in *Lint patterns* below. It does not flag other uses of `/` or `[` (`w-1/2`, `group/name`, `aspect-[16/9]`).
- **AC-4**: Inter is the only font family, self hosted through `next/font` so the browser never requests a font from another origin. Geist and Geist Mono are removed. Body text is 16px, secondary text is 14px, and nothing renders smaller than 14px: the `text-xs` size is removed from the theme.
- **AC-5**: The primitives in the Component inventory exist in `src/ui/` as named exports, one file each, each rendering the native element the inventory names.
- **AC-6**: Every interactive primitive is reachable with Tab in document order, operates with the keys its native element uses (Enter, Space), and shows a visible focus indicator on `:focus-visible`: a 2px `focus` coloured outline with a 2px offset. It is an `outline`, never a box shadow alone, so it survives forced colours mode.
- **AC-7**: Every interactive target is at least 24 by 24 CSS pixels (WCAG 2.5.8). Buttons are 40px tall at size `md` and 48px at size `lg`. In a checklist row the whole row is the click target for its checkbox, through its label.
- **AC-8**: The file picker has exactly one tab stop, the visible button. The native file input is `tabIndex={-1}` and `aria-hidden`, and it still receives files programmatically and from the button. Choosing a file still clears the input's value (spec 0002, AC-2).
- **AC-9**: A checklist row shows the match text as the checkbox's accessible name, with the page number right aligned in `ink-muted`. Below it, one 14px line shows `before`, the match inside a `<mark>`, then `after`. The mark uses an `accent-soft` background, `ink` text and semibold weight, so the highlight is not carried by colour alone. The page and the context line are the checkbox's accessible description. A long unbroken value (an email, a file name) wraps rather than being cut off.
- **AC-10**: A checklist group is a native `details` and `summary`, open by default, whose summary shows an icon, the group label, a count badge and a chevron that turns when the group is open. The count is announced with its noun ("2 items"), never as a bare number. The checkbox supports checked, unchecked and indeterminate states.
- **AC-11**: A callout comes in `warning`, `info` and `danger` tones. Each has its own icon shape and a visually hidden tone word ("Warning", "Note", "Error") ahead of its content, so tone is not carried by colour alone. It takes an optional title, a body, and an optional action (a secondary button). It sets no live region role of its own. The caller passes `role="alert"` when it appears in response to something the visitor did.
- **AC-12**: `/tool` is restyled from the primitives: the site header, one centred column no wider than 44rem, the title and intro with a lock icon, the drop zone, a live status region with a spinner beside the phase text, failures and the lost worker and unsupported browser messages as `danger` callouts, the opened document summary in a card, and Start over as a secondary button. The polite live region holds only the spinner, the phase text and the opened document card. The `danger` callouts (`role="alert"`) render beside it, never inside it, so no screen reader announces a failure twice. Every existing `data-testid`, role and accessible name is kept, so spec 0002's tests keep passing unchanged, apart from the one tab stop change in AC-8.
- **AC-13**: `/` is restyled: the site header carries a primary "Redact a PDF" button linking to `/tool`; the display headline reads "Truly redact a PDF."; the lead line reads "The text is removed from the file itself rather than covered with a black box, and your document never leaves your machine."; and a primary "Redact a PDF" button follows. There is no eyebrow on this page. Page metadata is unchanged.
- **AC-14**: Every page starts with a skip link, the first focusable element, that becomes visible on focus and moves focus to `<main id="main" tabIndex={-1}>`. `main` is the one element allowed to suppress its outline, because it is a focus target and not a control. The header is static (it scrolls away). Each page has exactly one `h1`, and `header`, `main` and `footer` landmarks. The footer carries spec 0011's Legal nav (AC-4), then spec 0009's licence notice (AC-1), all five links in `ink-muted` and underlined.
- **AC-15**: Both pages work at 320 CSS pixels wide without horizontal scrolling (WCAG 1.4.10), and with the root font size doubled nothing is clipped or overlapped (WCAG 1.4.4). No text size uses viewport units. No container that holds text has a fixed height, so text spacing overrides (WCAG 1.4.12) do not clip.
- **AC-16**: When the visitor asks for reduced motion (`prefers-reduced-motion: reduce`), the spinner stops turning and colour transitions are removed.
- **AC-17**: In forced colours mode (`forced-colors: active`), the focus outline, the drop zone edge, the callout edges, the highlighted match and the checkbox all stay visible. The checkbox falls back to the browser's native rendering.
- **AC-18**: axe (the automated accessibility checker), run with the `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` and `wcag22aa` rule tags, reports zero violations on `/` and on `/tool` in Playwright, in the idle, failed and opened states and again with forced colours emulated. It also reports zero violations on every primitive in the component tests, with the `color-contrast` and `target-size` rules off there, because jsdom computes no colour and no layout. AC-2 covers colour, and the Playwright runs cover size on the controls placed on a page.
- **AC-19**: `src/ui` is presentation only. It imports nothing from `@/worker`, `@/engine`, `@/config`, `@/lib/session` or `@/lib/entitlement`, and it never uses `dangerouslySetInnerHTML`. Both are enforced by an ESLint zone. Document derived strings reach a primitive only as props, are rendered only as React text, and are never written to `document.title` or the URL, because browser history is storage (spec 0002, INV-3).
- **AC-20**: This feature adds no request to any origin other than our own from `/` or `/tool`. Fonts are self hosted and icons are bundled. The tool route's content security policy is unchanged.
- **AC-21**: Every way into `/tool` from another page of ours is a real page load, so the tool page always runs in a document the browser loaded at `/tool`, under the tool route's own content security policy, with no script another route started still running. Both "Redact a PDF" buttons on `/` render a plain `a` through `Button`'s `reload` prop, never `next/link`, so `/` also no longer prefetches `/tool`. As a second line of defence, `ToolClient` checks which URL the current document was loaded at. If it was not `/tool` (a stray `next/link`, a `router.push`, or a sign in library redirecting on the client), it renders no drop zone, only the polite live region with the `Spinner` and "Loading the tool", does not warm the engine, and calls `location.reload()`, so no file can be chosen until the page has loaded properly. It reloads only when the address bar already reads `/tool` (`location.pathname === TOOL_PATH`), because a reload loads the address bar's URL and only a load at `/tool` can pass the check. When the address bar reads anything else, reloading would load the same wrong URL forever, so it does not reload: it renders no drop zone, does not warm the engine or ask for the entitlement, and returns only a `danger` `Callout` (`data-testid="wrong-url"`, no `role`, since nothing the visitor did caused it; a bare early return shaped like the unsupported callout) headed "This page cannot open a document" as a level 2 heading, with the line "The tool only works at its own address." and a secondary `Button` "Open the tool" to `TOOL_PATH` with `reload`. Nothing moves the visitor automatically from there. This check runs before the browser support check. When the browser does not report the load URL, the check passes and the page works as today.

## Decision

**Chosen option**: Option 1: Semantic tokens in Tailwind's theme, plus thin React primitives over native HTML in `src/ui/`.

Colours exist only as named roles in the Tailwind v4 `@theme` block, with the default palette wiped and every foreground and background pairing checked by a contrast test. The interface is composed from roughly a dozen small React components in `src/ui/` that render real `button`, `input`, `details`, `section` and `mark` elements, with no headless UI library and no class merging library.

**Implementation skills**: `next-best-practices` (`vercel-labs/openreview`, `.claude/skills/next-best-practices/`) for `next/font` and the server and client component split · `vercel-react-best-practices` (`vercel-labs/agent-skills`, `.claude/skills/vercel-react-best-practices/`) for keeping primitives server components where they hold no state

**State transitions** (visual states of the primitives; there is no data lifecycle)

- Drop zone: `idle` (dashed `border-strong` edge on `surface`) → `dragging` on drag over (solid `accent` edge, `accent-soft` fill) → `idle` on drag leave or drop. Choosing another file while one is opening stays allowed, as today.
- Checkbox: `unchecked` ↔ `checked`, plus `indeterminate`, which only the caller sets and a click clears.
- Checklist group: `open` (first render) ↔ `closed`, owned by the browser through `details`. Nothing remembers it.
- Button: default, hover, active, `focus-visible`, `disabled` (`subtle` fill, `ink-muted` text, `border` edge, and not reachable by Tab because it is a disabled native `button`).

- The load guard (AC-21): `loadedAt(): string | null` in `src/lib/document-load.ts` returns `new URL(entry.name).pathname` for `performance.getEntriesByType("navigation")[0]`, or `null` when the browser gives no entry. The guard compares it to `TOOL_PATH` exactly, with no trimming: Next.js already redirects `/tool/` to `/tool`, and a query string is not part of the pathname. It is read once and cached, like `getSupport()`. The decision is a pure function beside it, `loadGuard(loadedAt: string | null, address: string): "ok" | "reload" | "wrong-url"`: `"ok"` when `loadedAt` is `null` or equals `TOOL_PATH` (a document the browser loaded at `/tool` is under the right policy, whatever the address bar says later); otherwise `"reload"` when `address` equals `TOOL_PATH` exactly, and `"wrong-url"` for anything else, `/tool/` included. `currentPath(): string` returns `location.pathname`, uncached. `ToolClient` reads `currentPath` through a second `useSyncExternalStore` with the same `NEVER_CHANGES` subscription and the same `TOOL_PATH` server snapshot, calls `reloadDocument()` from an effect only on `"reload"`, shows "Loading the tool" on `"reload"` and, on `"wrong-url"`, returns the wrong URL callout alone, as the unsupported branch does, so it sits outside the polite live region and carries no `role` (AC-11, AC-12). `ToolClient` reads it through `useSyncExternalStore` with a server snapshot of `TOOL_PATH`, which is honest: the prerendered HTML is only ever used by a document the browser loaded at `/tool`. `TOOL_PATH = "/tool"` lives in `src/lib/routes.ts`. `next.config.ts` keeps its own `/tool` match, with a comment pointing at the constant, because the header rule is a regular expression.
- Root layout: `SkipLink` first in `body`, `SiteFooter` last. Each page renders its own `SiteHeader` and `<main id="main">`.
- Built but not placed on a page by this feature: `Checkbox`, `CountBadge`, `ChecklistGroup`, `ChecklistItem`, `EmptyState` and the `eyebrow` utility. Component tests carry them until features 8 and 15 place them.

**Lint patterns** (AC-3). Both are `no-restricted-syntax` selectors applied to `Literal[value=/.../]` and to `TemplateElement[value.raw=/.../]`, so class names in plain strings and in template literals are both caught. `P` is the colour utility prefix group:

```text
P = (bg|text|border(-[xytrblse])?|ring(-offset)?|outline|decoration|divide|fill|stroke|accent|caret|from|via|to|shadow|inset-shadow|placeholder)

alpha modifier:   (^|[\s:!])P-[a-z0-9-]+\/(\d{1,3}|\[)
arbitrary colour: (^|[\s:!])P-\[(#|(rgba?|hsla?|hwb|lab|lch|oklab|oklch|color)\()
```

The alpha pattern also rejects Tailwind's `text-<size>/<leading>` shorthand. That is deliberate: the type scale sets line height, so nothing needs the shorthand.

**Key invariants**

- **INV-1**: Every colour on screen is a token from the Token table. The wiped palette makes any other named colour fail to generate, and the lint rule in AC-3 rejects arbitrary values.
- **INV-2**: Every foreground and background pairing that ships appears in the Contrast contract and passes it. A new pairing is added to the contract and the test in the same change that introduces it.
- **INV-3**: Text never gets its colour from opacity or an alpha modifier. A quieter text colour is `ink-muted`, never `ink` at 70%.
- **INV-4**: Primitives render native elements with native semantics. No `div` plays a button, and no ARIA role repeats what the element already is.
- **INV-5**: Focus is always visible. No primitive removes the outline without replacing it, and the replacement is always an `outline` with a 2px offset. The only exception is `main` as the skip link's target (AC-14).
- **INV-6**: One font family (Inter). Nothing renders below 14px. No text size uses viewport units.
- **INV-7**: `src/ui` is presentation only (AC-19). Document derived text is untrusted input, reaches a primitive only as a prop, and is rendered only as React text children.
- **INV-8**: Nothing is conveyed by colour alone. Callout tone has an icon shape and a hidden tone word, the highlighted match is also semibold, and links are always underlined, with one exception: the header's nav items are identified by their place in the labelled nav row and are not underlined at rest, and the current page's item is marked by `aria-current`, semibold text and a 2 pixel `accent` bar as well as colour (spec 0013, AC-7). Footer links and links in running text stay underlined.
- **INV-9**: Nothing about the interface is remembered between visits. Group open state, drag state and everything else live in memory only (spec 0002, INV-3).
- **INV-10**: A document is only ever opened in a page the browser loaded at `/tool` (AC-21). A content security policy belongs to the document it arrived with, so a client side navigation into `/tool` would keep the policy and the scripts of the page it came from. This is the inbound half of the rule the wordmark already keeps on the way out (spec 0002, INV-6). Only `src/app/tool/page.tsx` renders `ToolClient`, which INV-11 enforces.
- **INV-11**: The load guard can never cause a reload loop. It loads a page automatically only when the address bar reads exactly `TOOL_PATH`, and the document that load produces is one the browser loaded at `TOOL_PATH`, so it passes. At any other address it fails closed and waits for a click. On top of that, lint makes `src/app/tool/page.tsx` the only module that may import `tool-client` (AC-3's zones), so the wrong URL state is a bug the linter reports rather than one a visitor finds.

**Security model**

No accounts, roles or data are involved; the primitives are public presentation. What they must defend against:

- **Untrusted document text.** A match or its context can contain anything a PDF author typed, including markup. It renders only as React text, which escapes it, and `dangerouslySetInnerHTML` is banned in `src/ui` by lint.
- **History as storage.** Document derived text never goes into `document.title`, the URL or its hash, because the browser writes both to history.
- **Third party origins.** Fonts are self hosted at build time, icons are compiled into our bundle, and no image or stylesheet comes from a CDN. The tool route's CSP (`font-src 'self'`, `img-src 'self' data: blob:`, `connect-src 'self'`) is unchanged, and this design needs nothing it does not already allow.
- **Crossing between the two policies.** `/tool` and every other route get different content security policies (spec 0001), and today they happen to be identical. Once features 10 and 11 add third party origins to the standard policy, a client side navigation from `/` would open the visitor's document under that looser policy, with auth and analytics scripts still alive, while the `/tool` response header still looked correct to every header test. AC-21 closes this in two layers: the links we ship are real page loads, and the tool page refuses to accept a file in a document that was not loaded at `/tool`. The guard stops a file being opened under the wrong policy. It does not stop scripts the earlier page started from running until the reload ends them, which is why the plain links, not the guard, are the main defence.
- **Compliance.** GDPR scope is inherited from spec 0001 and unaffected: nothing new is collected.

**Configuration required**

None. No new environment variables. New packages: `lucide-react` (dependency), `axe-core` and `@axe-core/playwright` (development dependencies). Inter comes through `next/font/google`, which needs no package.

## Consequences

**Positive**:

- Features 6, 7, 8 and 15 compose decided, tested pieces. None of them has to invent a checkbox row, a warning card or a colour, and none of them can quietly add an untested one.
- Contrast is a test failure, not a review comment. A token change that breaks a pairing fails CI before anyone looks at a screen.
- Native `button`, `input`, `details` and `mark` bring keyboard handling, focus order and screen reader semantics with them, so the accessibility code we own is mostly class names and a handful of `aria-describedby` wires.
- Three small packages and nothing third party at runtime. The tool route's CSP does not move, and neither does the privacy claim.
- Most primitives are server components, so the home page ships almost no extra JavaScript.

**Negative and tradeoffs**:

- **Light only.** A visitor whose system prefers dark gets a bright page. Adding dark later means redefining every role and doubling the contrast contract and the axe runs. A toggle was never available, since nothing can be stored to remember it.
- **The unplaced primitives are proved only in jsdom** until feature 8 puts them on `/tool`. jsdom computes no layout, no contrast and no forced colours, so the checkbox's forced colours fallback in particular has no real browser proof yet. The token test covers colour; nothing covers the rest until then.
- **The lost worker state has no real browser run.** Playwright cannot kill a worker, so the `lost` callout is proved only in jsdom. It reuses the same `danger` callout and secondary button that the failed state proves in the browser, which narrows the gap without closing it.
- **`summary` cannot hold an interactive control.** A "select all in this group" checkbox cannot live in the group heading, so feature 8 has to put it in the card header or as the group's first row.
- **Wiping the palette is friction on purpose.** A pasted Tailwind snippet using `gray-500` silently renders no colour, and every new shade means a token, a contract row and a test pair.
- **The contrast test parses CSS with a pattern**, so the token format is fixed at `--color-<role>: #RRGGBB;`. Moving to `oklch()` or another notation breaks the test, loudly, until the parser is extended.
- **The drop zone now owns the file input**, which moves one of spec 0002's guarantees (clearing `input.value`, AC-2) into `src/ui`. It is tested there, but it is a privacy rule living in a presentation folder.
- **The summary panel the scope row names is not built here.** Feature 8 owns it, so feature 4 is done without it.
- **The tool page is no longer prefetched from `/`**, so "Redact a PDF" costs a real document load instead of an instant swap. The page is static and cached, and the engine loads on the tool page either way, so the visible cost is small.
- **The guard passes when the browser gives no load URL.** Every browser that has the other capabilities RedactNest needs reports one, and the plain links are the first defence, so failing closed here would mostly mean a false "cannot run in this browser" for nobody's benefit.
- **A tool page at the wrong URL is a dead end with one button.** It can only happen through our own mistake (lint blocks the usual one), and a click is the price of never looping.
- **The guard's only proof is in jsdom**, because once the links are plain nothing we ship can make a client side navigation into `/tool` for Playwright to follow.
- **axe finds only part of what WCAG covers.** A clean axe run does not replace the keyboard and screen reader pass at `/check verify`.

**Neutral**:

- A new top level folder, `src/ui`, joins the capability folders AGENTS.md lists.
- One existing browser test is rewritten (the tab stop) and two are narrowed to `main` (the duplicate link). Spec 0002's behaviour is otherwise untouched.
- `lucide-react` must be imported by name. Next.js already optimises its imports, but a namespace import (`import * as Icons`) would still pull the whole set in.
- Inter replaces Geist at a similar download size, so first load weight is roughly unchanged.
