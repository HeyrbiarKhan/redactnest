## Summary

Feature 31's fresh model review ([2026-11-15](../../reviews/2026-11-15-feat-kept-object-leaks.md)) left five small gaps in the allowlist spec 0019 built, and this spec closes them inside that design. The file's language entry (`/Lang`) is kept only when it is a real language tag holding nothing you ticked, a CID font's two identifying strings must be short codes or the file is refused at open, and the self check now fails any run that leaves a ticked item's text in either place. The drawing scan gives up after 16 retries instead of running for about an hour on a crafted stream, and it counts an indexed inline picture's named colour space as used. The check after the second write compares every stream it can reach, not only figures and pictures. One problem found while measuring (MuPDF drops an inline picture whose indexed colour space is written inline) is recorded here and designed next, on its own.

## Requirements

**User stories**:
- As a visitor, I want a value I ticked to be gone from the whole file even when the file's language entry or a font's identifying strings repeat it, so a file that passes the check cannot still hold it there.
- As a visitor, I want a file with an odd language entry to be cleaned, not refused after I have ticked, since no page needs that entry to draw.
- As a visitor, I want a page whose inline description holds a hyphenated name to be warned about, as a page holding any other name is.
- As a visitor, I want a crafted file to be warned about or refused within a second or two, not to keep my tab busy for an hour.
- As a visitor, I want a file that needs the second write to come back drawing exactly what the first write drew, or not at all.

**Acceptance criteria**:

- **AC-1**: **The catalog's language.** `graftPages` in `rebuild.ts` copies the working copy's catalog `/Lang` into the new document only when it is a string that reads as a language tag (`readsAsLanguageTag`, AC-2) and holds no ticked item's text (`holdsTicked`, AC-4). It reads the string's bytes with `asByteString()` and decodes them as the scan decodes a string: UTF-16BE after the `FE FF` mark, PDFDocEncoding otherwise. One decoder, `decodeTextString` in `allowlist.ts`, serves the scan, the walk, the rebuild and the check. _As built (2026-11-21)_: it reads the real PDFDocEncoding table, so bytes 0x18 to 0x1F and 0x80 to 0xA0 take the characters that encoding gives them, which differ from Latin 1 (0x95 is `Ł`, 0x93 the fi ligature), and every other byte is its Latin 1 character; a UTF-16 string of an odd length cannot be decoded. Any other `/Lang` (free text, a name, a number, an empty string, a string that cannot be decoded, or a tag holding a ticked text, such as `en-GB` with `GB` ticked) is left out: the cleaned file has no `/Lang`, the run neither refuses nor reports it, and `sanitized` is unchanged. A tag that is kept is copied as written (`graftObject`), direct or indirect. The role table's catalog `/Lang` becomes a language tag string, so the structure check fails an output whose catalog `/Lang` is anything else with `redaction-incomplete` (spec 0019, AC-5), and AC-4's check fails one holding a ticked text. The open never reads the catalog and refuses nothing for it. Measured on a document built in a scratch test, nothing ticked (2026-11-18): `/Lang (Jane Smith 123-45-6789)` left in the output with the check passing, and `/Lang /en-US` opened, then refused the run with `unreadable-structure`. After this, both make a file with no `/Lang`.

- **AC-2**: **What reads as a language tag.** `LANG_TAG` matches the whole decoded string, letters in either case: a language of two or three ASCII letters; then, each after a hyphen or an underscore, each optional and in this order, a script of four letters, a region of two letters or three digits, and any number of variants of a digit followed by three letters or digits. Written out: `^[A-Za-z]{2,3}(?:[-_][A-Za-z]{4})?(?:[-_](?:[A-Za-z]{2}|[0-9]{3}))?(?:[-_][0-9][A-Za-z0-9]{3})*$`.
  - Read as tags: `en`, `deu`, `EN-gb`, `en-GB`, `en_US`, `es-419`, `zh-Hant-TW`, `sr-Latn-RS-1994`, `de-DE-1996`.
  - Not tags: `Amy-Jones`, `Bob_Smith`, `Jane Smith`, `english`, `e`, `12`, `en-`, `en--GB`, `en-GB ` (a trailing space), `en-toolongsubtag`, `x-none`, `sl-rozaj`.
  - A short name that fits the shape (`Doe`, `Amy-Rose`, `Ann-Li`) still reads as a tag. Unticked, it can stay, as spec 0019 already says unticked text can; ticked, AC-1 leaves it out of the catalog and an inline one keeps spec 0019's warning rules. The comment above the pattern says so, and a test pins those three as tags, so a later change is deliberate.
  - Real tags the shape leaves out (private use such as `x-none`, a variant of five to eight letters such as `rozaj`, an extended language such as `zh-yue`) now count as text: an inline one warns with `marked-descriptions`, and a catalog one is left out (AC-1).
  - One pattern and one decoder serve the scan's inline rule (spec 0019, AC-9), the rebuild and the walk. `LANG_TAG` and `readsAsLanguageTag(bytes)` (today's `isLanguageTag` in `marked.ts`, renamed) move to `allowlist.ts` beside `STRING_PLACES`, and `marked.ts` imports them. `marked-descriptions.pdf` and spec 0019's AC-10 pins are unchanged: `en-GB` and `en_US` stay quiet and `Jane Smith` warns.

- **AC-3**: **A CID font's identifying strings.** A `CIDSystemInfo`'s `/Registry` and `/Ordering`, wherever the walk reaches one (a CID font, or a character map), must each be a string whose raw bytes match `CID_TOKEN`, `^(?:[A-Za-z][A-Za-z0-9]{0,15})?$`: empty, or an ASCII letter followed by up to 15 ASCII letters or digits. So a hyphen, an underscore, a space, a leading digit or any byte outside ASCII refuses, and `123-45-6789`, `Rowan-Ashby` and `Rowan Ashby` never pass. Every value Adobe defines (`Adobe`; `Identity`, `UCS`, `Japan1`, `Japan2`, `GB1`, `CNS1`, `Korea1`, `KR`) passes, as does every value in the committed fixtures (`Adobe` with `Identity` or `UCS`).
  - `StringPlace` gains `text: "language-tag" | "token" | "any"`: the catalog's `/Lang` a language tag, `/Registry` and `/Ordering` a token, the `/Indexed` palette and `/ActualText` any. The one shared `STRING` shape becomes three (`LANG_STRING`, `TOKEN_STRING`, `ANY_STRING`), each carrying its `text`. `tests/unit/allowlist.test.ts` holds every role keyed place's `text` equal to the string shape `ROLES` gives that key, and the palette arm's `text` as `any`; no shape reads the palette's `text`, since the palette shape is binary and stays as it is.
  - A string outside its `text` is a value in a shape the format never gives that key (spec 0019, INV-2): the role walk answers `"shape"`, so the open refuses the file with `unreadable-structure` (its walk reaches fonts from each page), a run refuses it before anything is written (the glyph rule's walk answers `"problem"` first), and the structure check fails an output holding one with `redaction-incomplete`. A value that is not a string is refused as today. The words are spec 0019's AC-3 words, unchanged, and the open names no page.
  - These two strings name the character collection a CID font's codes come from, which can change how a reader draws and reads its text, so the walk refuses rather than deletes them. What the token still lets through, a run together name or code such as `RowanAshby` or `ACME12345`, stays only when unticked (AC-4).

- **AC-4**: **No ticked text at a string place.** `checkOutput` (`self-check.ts`) fails the output with `redaction-incomplete` when the catalog's `/Lang`, or a string at `/Registry` or `/Ordering` in any dictionary (`forEachDictionary`, read through references), holds a ticked item's text: `holdsTicked(text, ticked)` is true when the place's folded text contains the folded `text` of any target in the run (`RedactionTarget.text`). Folding is `foldPlaceText`: lowercase, then NFKD, then keep only letters and digits (`\p{L}` and `\p{N}`), so case, accents and every space, hyphen or underscore drop out, and `Rowan Ashby` folds to `rowanashby`, matching an `/Ordering (RowanAshby)`. A target whose folded text is empty is skipped. A `/Registry` that is exactly `Adobe`, or an `/Ordering` that is exactly one of `Identity`, `UCS`, `Japan1`, `Japan2`, `GB1`, `CNS1`, `Korea1` or `KR` (`ADOBE_COLLECTIONS`), is never compared: these are the format's own words, the same in every file and never taken from the document, so ticking `ID`, `Adobe` or `Japan` does not refuse every file with such a font. A ticked word that matches one stays, as a ticked word matching a font's name already does (spec 0019's names limit).
  - It runs in `checkOutput` itself, right after the structure part and before `"rewrite"` is answered or any page is compared, never through the `Pipeline` seam's `checkStructure`. So a hit is a leak: it outranks `unreadable` and `unused-colour-space`, never leads to a second write, and runs again on the second write's bytes. A run with nothing ticked has no texts and passes it.
  - The rebuild needs the same texts for AC-1: `redactDocument` folds every target's `text` once and hands the list to `graftPages`, and the check folds the same way, so the two never disagree. The folded texts are document text: they live only inside the worker for the length of the run, as the character record does, and are never logged or sent.
  - _As built (2026-11-21)_: a place's text is its string decoded by `decodeTextString` (AC-1). A string at one of the three places that cannot be decoded (a UTF-16 string of an odd length) may hold anything, so whenever anything is ticked it counts as holding a ticked text and the check fails with `redaction-incomplete` (`placeHoldsTicked` in `self-check.ts`). With nothing ticked this part passes, as it does for every string. The walk refuses such a string at all three places first (one that cannot be decoded reads as no language tag, and its `FE FF` mark puts a byte outside ASCII in a token), so only a run whose structure check is swapped out meets this rule; it keeps INV-3 true without leaning on the walk.
  - `/ActualText` is outside this check; it keeps spec 0019's rules (*Follow-up*).
    _Amended by spec [0023](../0023-ticked-text-in-descriptions/index.md), AC-2: `/ActualText` and every other description string in a drawing are held by spec 0023's check, inside the structure part, which fails the run with `replacement-text`._

- **AC-5**: **The cases fail first.** Two committed fixtures written by `scripts/make-fixture.mjs` through `scripts/lib/kept-fixtures.mjs` (never by MuPDF), each one page of 612 by 792 points with one line at 72, 700, size 18, and tests in `tests/unit/redaction-kept.test.ts` that read outputs with `tests/support/mupdf.ts` only (spec 0004, INV-3: a list change has a failing fixture as its proof):
  - `kept-lang.pdf`: the line reads "Prepared by Quinn Harlow" in Helvetica, and the catalog holds `/Lang (Quinn Harlow)`; `KEPT_TEXT.lang` is `Quinn Harlow`. With `Quinn Harlow` ticked, the output's decompressed bytes hold it in neither string encoding (`containsInAnyEncoding`, spec 0004's AC-4) and its catalog holds no `/Lang`. With nothing ticked, its catalog holds no `/Lang`. On today's code the ticked run keeps the name in `/Lang`, so the test fails first.
  - `kept-cid-strings.pdf`: the line reads "Prepared by Rowan Ashby" in a Type 0 font that `kept-fixtures.mjs` builds itself, importing `IDENTITY_UNICODE` from `scripts/lib/redaction-fixtures.mjs` (two byte codes that are Unicode code points, that ToUnicode map, a font descriptor, `/DW 600`, no font program; `scripts/lib/detection-fixtures.mjs` is not changed), with `/Registry (Adobe)` and `/Ordering (Rowan Ashby)`; `KEPT_TEXT.ordering` is `Rowan Ashby`. It is refused at open with `unreadable-structure`, before a review, and a run handed its bytes directly with `Rowan Ashby` ticked is refused the same way. Measured on today's code (2026-11-18, the same recipe built in a scratch test): it opens, and that run makes a file still holding the name in `/Ordering`, so the test fails first.
  - Both join the gate (spec 0019, AC-7): `MAIN_FIXTURES` in sorted order, their open, run and `sanitized` rows read from 5c4e0d7's code (a `git archive` of it, never the current code). `kept-lang.pdf` gets its ticked set in `NEEDLES` (its name) and keeps main's outcome, counts, `sanitized` and pixels. Its pixel check says nothing about `/Lang`: the gate's main pipeline swaps only the prune and the structure check, so it runs the same `graftPages` and leaves `/Lang` out too. The committed test above is what holds `/Lang`.
  - `kept-cid-strings.pdf` goes in `OPEN_NOW` as `unreadable-structure` and has no `NEEDLES` row. _As built (2026-11-21)_: this criterion first gave both fixtures a ticked set, but the gate's table check ("tick only fixtures that open and run") forbids one for a fixture refused at open, as it does for spec 0020's four refused glyph fixtures. Its ticked run's refusal is held in `redaction-kept.test.ts` alone, by the run handed its bytes in the second bullet above ("refuses a run handed its bytes with the name ticked").
  - AC-4's check on its own, on documents built in the test: one whose page line and `/Ordering` both hold `ACME12345` (which the token lets through), run with `ACME12345` ticked, fails with `redaction-incomplete` and makes no file, and with nothing ticked makes a file. The string place check (`checkOutput` on bytes built in the test, with the ticked texts handed in) fails `/Lang (Amy-Rose)` with `Amy-Rose` ticked, `/Ordering (RowanAshby)` with `Rowan Ashby` ticked and `/Ordering (Rowanx1)` with `rowan` ticked, and passes `/Ordering (Identity)` with `ID` ticked and `/Registry (Adobe)` with `Adobe` ticked, since `ADOBE_COLLECTIONS` skips both (`holdsTicked` itself is plain containment and answers true for those two). Today's code has no such check and lets all three through, so those tests fail first.

- **AC-6**: **The scan's retries.** In `scanContent` (`marked.ts`), one count per call: `retry` adds one each time it gives a choice a new end, and before giving one, returns false (so the stream is `"unsure"`) once the count has reached `INLINE_END_RETRIES` (16). A choice popped with no end left takes none and adds nothing. `"unsure"` already warns at open (spec 0019, AC-9), fails the check with `unsupported` unless a leak outranks it (its AC-5), and counts as the worst a glyph could draw (spec 0020, AC-4).
  - The count test, in `marked.test.ts`: `BI /W 1 /H 1 /BPC 8 /CS /G ID x`, then ` EI )` written N times, then ` EI Q`. Each false end resumes on a stray `)` and fails; the real end resumes on `Q` and reads. With N = 16 the stream reads to its end; with N = 17 it answers `"unsure"` (today it reads, so the test fails first).
  - The cost test, in `tests/unit/cost.test.ts`: `BI /W 1 /H 1 /BPC 8 /CS /G ID `, then ` EI 1` written 200,000 times, then ` (`, about 1 MB, answers `"unsure"` in at most 2,000 ms, the least of three passes after a warm up. Measured today (2026-11-18): 2.5 KB of it took 26 ms, 5 KB 101 ms and 10 KB 393 ms, growing with the square of the length, so 1 MB would take about an hour; a plain 1 MB stream reads in 35 ms, so 17 reads of 1 MB come to about 0.6 s.
  - `INLINE_END_RETRIES` is an engine constant, a rule about the scan rather than a cap on the visitor (spec 0019, INV-5), commented as such.

- **AC-7**: **An indexed inline colour space names its base.** In `inlineImage` (`marked.ts`), an inline picture's `/CS` or `/ColorSpace` is a colour space use when it is a name that is not in `INLINE_DEVICE_SPACES` (as today), or when it is an array whose first item is the name `/I` or `/Indexed` and whose second item is such a name; that second name is recorded under `ColorSpace` (spec 0019, *Resource use*). A device base (`[/I /G ...]`, `[/Indexed /DeviceRGB ...]`) records nothing, and nothing else inside an array counts: the format allows a named resource only at an indexed space's base. This is a change to the scan alone, held by its unit tests and a pin: measured on MuPDF 1.28.1 (2026-11-18, documents built in a scratch test), an inline picture whose `/CS` is `[/I /Cs1 1 <FF0000 00FF00>]`, with `/Cs1` a calibrated RGB space in the page's resources, is not drawn in the source, and a run with nothing ticked makes a file holding neither the picture nor the `/Cs1` entry. So no output reaches the case today. The pin in `redaction-kept.test.ts` holds that behaviour, so a release that starts drawing such a picture fails it and shows the rule now matters.

- **AC-8**: **The drawn shape.** `drawnShape` (`self-check.ts`) records, for every object `walkRoles` reaches in a role whose form in `ROLES` is `stream` or `either` (derived from `ROLES`, never a list written by hand: today content, form, image, font file, character map, tiling pattern, shading, function, colour profile and plain stream), its stored length read raw through its reference, or `-1` when it is not a stream, listed under each such role it is reached in, each list sorted. `sameDrawnShape(first, second)` holds when every role's two lists are equal, except `colour-profile` (`BELOW_COLOUR_ROLES`, a set of one), where every length in the second's list must be matched by an equal length in the first's, one for one: the second write may lose a whole profile, never change one. A `-1` matches only a `-1`. Otherwise the run fails with `unsupported`, once the full check on the new bytes has passed, as today (spec 0019, AC-15). So a second write that drops or changes a font file, a character map, a tiling pattern, a shading, a function, a palette stream or a glyph procedure, or turns any reached stream into a bare dictionary, fails the run.
  - Measured on the five colour fixtures (2026-11-18): content and form lengths were equal across the two writes, and only the 45 byte unreadable profiles went (three of the five), so all five still make a file. Equal lengths on every role failed all three of those.
  - Not measured yet: a font file, tiling pattern or shading through the second write. Task 10 runs one first (a document with the unreadable profile beside a Carlito font file, a tiling pattern and a type 4 shading, through the real `rewrite`), and it must make a file. If it does not, or if any colour fixture fails with `unsupported`, the build stops and brings the measurement back to `/architect`.

- **AC-9**: **Nothing else changes.** Every committed fixture keeps the open and run outcome, `removedByType`, `sanitized` and pixels the gate holds (spec 0019, AC-7), except `kept-cid-strings.pdf`, refused at open on purpose (`OPEN_NOW`). That rests on the gate's run: no committed fixture holds a catalog `/Lang` but `metadata.pdf`'s `en-GB`, and none holds a ticked text at a string place. No committed fixture newly warns with `marked-descriptions` (spec 0019, AC-10). Both spec 0019 budgets (its AC-11) and spec 0006's open budget pass. No word on `/`, `/tool` or `/security` changes: the security page's structure item holds keys and strings to lists in its own words and names no string place, and `unreadable-structure`'s words say only that part of the file is built in a way RedactNest can't check safely (spec 0018, AC-5). The source comment above the structure item that says the lists keep the catalog's `/Lang` adds "when it reads as a language tag and holds nothing ticked (spec 0021)".

## Decision

**Chosen option**: Option 1, hold each to the shape the format gives it, in place, inside spec 0019's design, with the self check holding the ticked value at every place a shape cannot.

The two string places take the format's own shape: a catalog `/Lang` no page needs is left out when it is not a tag or holds a ticked text, and a CID font's strings, which a page may need, are refused when they are not a short token. The check then fails any run whose `/Lang`, `/Registry` or `/Ordering` still holds a ticked item's text, Adobe's own values aside. The scan's work on a stream is bounded by a fixed number of reads, it reads an indexed base name as the format writes one, and the drawn shape covers every stream the walk reaches, with only colour profiles allowed to go. Runner up: record all five as limits and change no code, which leaves a ticked value in the catalog's `/Lang` and a scan an hour long.

| check | a ticked text at a string place | `holdsTicked` over the catalog's `/Lang` and every `/Registry` and `/Ordering` string not in `ADOBE_COLLECTIONS`, each decoded by `decodeTextString`, so `redaction-incomplete`; one that cannot be decoded is a hit whenever anything is ticked |
| inspect | whether an inline `/Lang` counts | `readsAsLanguageTag` on the property list's string (spec 0019, AC-9) |
| scan | whether a retry is left | `INLINE_END_RETRIES` less the new ends this call has given |
| scan | the colour space an inline picture names | its `/CS` or `/ColorSpace`: a name, or the second item of an `/I` or `/Indexed` array; device spaces from `INLINE_DEVICE_SPACES` |
| run | whether the second write kept what the first drew | `drawnShape` of both bytes over the stream roles `ROLES` names, compared by `sameDrawnShape` with `BELOW_COLOUR_ROLES` |

**Key invariants**:
- **INV-1**: A string place's rule lives once (`STRING_PLACES`' `text`, `LANG_TAG`, `CID_TOKEN`), and one fold (`foldPlaceText`) serves the rebuild and the check, so the inline and catalog language rules never disagree, and the rebuild never keeps a `/Lang` the check would fail.
- **INV-2**: What no page needs to draw is left out when it fails its shape or holds a ticked text (the catalog's `/Lang`); what a page may need is refused when it fails its shape (`/Registry`, `/Ordering`), and the check refuses the run when it holds a ticked text. Neither is ever rewritten (spec 0019, INV-2 and INV-7).
- **INV-3**: No ticked item's text stays at a string place this spec names with the check passing, except as one of Adobe's own values, whole. The check reads the output's bytes, whether or not the rebuild did its part, and treats a string there it cannot decode as holding a ticked text whenever anything is ticked.
- **INV-4**: The scan reads one stream at most `INLINE_END_RETRIES` + 1 times. Running out is doubt, and doubt warns or refuses, never passes a file (spec 0019, INV-4).
- **INV-5**: The second write may drop only whole colour profiles. Any other difference in the stored lengths the walk reaches fails the run (spec 0019, INV-8).
- **INV-6**: `LANG_TAG`, `CID_TOKEN`, `ADOBE_COLLECTIONS`, `INLINE_END_RETRIES` and `BELOW_COLOUR_ROLES` are engine constants, rules about the format and the scan rather than caps on the visitor, so no environment variable can change them (spec 0019, INV-5).

**Security model**: no new authorisation; the tool stays anonymous. The folded ticked texts are document text: they stay inside the worker for the length of the run, like the character record, and are never logged, sent or held past it. Nothing new crosses the worker boundary. `unreadable-structure` now has a third way in (the token, beside the role walk's other shapes and the glyph rule), and `redaction-incomplete` one more cause (a ticked text at a string place), each still counted as one kind, so telemetry cannot tell them apart; no catalog or privacy policy change (spec 0016).

**Configuration required**: none.

## Consequences

**Positive**:
- A ticked item's text no longer stays in the catalog's `/Lang`, a `/Registry` or an `/Ordering` with the check passing, except as one of Adobe's own values, whole, so spec 0004's AC-4 holds at those places; and the check fails such a file rather than trusting the rebuild.
- A catalog `/Lang` written as a name no longer refuses a run after the visitor has ticked.
- The inline and catalog language rules agree, and a hyphenated name in an inline `/Lang` warns.
- A crafted stream costs a second or so at open, not about an hour.
- The second write can no longer drop or change a font file, a pattern, a shading, a function or a glyph procedure unseen.

**Negative / tradeoffs**:
- A real file whose `/Registry` or `/Ordering` falls outside the token is refused at open. Real files were not measured; the counts cannot tell this cause from the role walk's other shapes or the glyph rule.
- A run whose ticked text appears inside a font's non Adobe `/Registry` or `/Ordering` fails with `redaction-incomplete` and makes no file; a short ticked term (two characters are allowed) raises the odds of a chance match there.
- A ticked word that equals one of Adobe's own values (`Adobe`, `Identity`, `Japan1` and the rest) stays in the file, as a ticked word that equals a font's name does.
- Real language tags outside the shape (private use, long variants, extended languages), and a tag holding a ticked text, are left out of the catalog, so a screen reader loses the file's language on such a file; inline, the first kind now warns.
- Unticked short names that fit the tag shape (`Doe`, `Amy-Rose`, `Ann-Li`) and unticked run together codes that fit the token (`RowanAshby`, `ACME12345`) still stay, as spec 0019 says unticked text can.
- A real stream with more than 16 false inline ends is unsure: a warning at open, then `unsupported` in the run. Random data holds a false end about once in 45 MB, so this should not happen, but it was not measured on real files.
- A second write that needs to drop a function or palette below a colour space MuPDF cannot load now fails the run with `unsupported`, rather than passing; no committed fixture or probe does that, and such a file comes back to `/architect`.
- The drawn shape compares stored lengths, not contents, so a second write that changed a stream's bytes and kept its length still passes, as it did for pictures.
- Until its own design lands, an inline picture whose indexed space is written inline still vanishes from the cleaned copy with the check passing (*Follow-up*). It loses ink, never keeps content.

**Neutral**:
- A second fixture refused on purpose joins `OPEN_NOW`.
- `LANG_TAG` moves from `marked.ts` to `allowlist.ts`; its export from `@/engine` follows.
- `graftPages` and `checkOutput` take the run's folded ticked texts; tests that call them directly pass `[]`.
