# src/engine

The redaction engine: MuPDF compiled to WebAssembly, behind the engine wall. It refuses what is not a PDF, opens and prepares the review copy, and redacts a fresh working copy of the original into a rebuilt file that it checks before anything leaves. The decision is [spec 0004](../../docs/specs/0004-redaction-engine/index.md), with the measurements behind it in [rationale.md](../../docs/specs/0004-redaction-engine/rationale.md). The wall itself is [spec 0001](../../docs/specs/0001-browser-only-redaction-stack/index.md). Reading every page before review, and trimming what lies outside each page's visible area, is [spec 0006](../../docs/specs/0006-scanned-page-detection-warnings/index.md), with its measurements in [rationale.md](../../docs/specs/0006-scanned-page-detection-warnings/rationale.md). The typed allowlist below the pages, the structure check that holds it, the second write and the `.resolve()` ban are [spec 0019](../../docs/specs/0019-kept-object-allowlist/index.md), with its measurements in [rationale.md](../../docs/specs/0019-kept-object-allowlist/rationale.md). The glyph rule, which refuses a file whose Type 3 glyphs show text or share a drawing with anything outside the fonts, is [spec 0020](../../docs/specs/0020-type3-glyphs-stay-in-font/index.md), with its measurements in [rationale.md](../../docs/specs/0020-type3-glyphs-stay-in-font/rationale.md). What each string place must read as (the catalog's `/Lang`, a `CIDSystemInfo`'s `/Registry` and `/Ordering`), the check for a ticked text there, the scan's retry cap and the drawn shape over every stream role are [spec 0021](../../docs/specs/0021-allowlist-follow-ups/index.md), with its measurements in [rationale.md](../../docs/specs/0021-allowlist-follow-ups/rationale.md).

## Files

- One file per step, mapped in the header of `index.ts`. `index.ts` is the only entry: callers import from `@/engine`, never from a file inside it.
- Only `src/worker/engine.worker.ts` imports this folder, and only this folder names `mupdf`. The `redactnest/engine-wall` lint zones enforce both. `tests/` sits outside the wall on purpose, because a test of the walled module has to import it.
- `objects.ts` holds the small readers over MuPDF's object model that the inventory, the rebuild and the self check share, so all three agree on what "an object carries a key" means. `forEachDictionary` hands each numbered object to its visitor as its reference (`doc.newIndirect(num)`), never resolved, and a dictionary written directly inside one as itself. Spec 0019, AC-16.
- `allowlist.ts` is the typed allowlist below the pages (spec 0019). `walkRoles` gives every object a role from the key and role of the object that reached it, never from what the object says about itself (INV-1), and checks each kept key's value against its shape in `ROLES`. In `"prune"` mode it deletes every key off its role's list at any depth; in `"read"` mode it only reports. Either way it hands back the first problem (a shape the format never gives that key, or an object reached in roles it cannot satisfy together), every object reached with its roles, each page's drawing streams, and the resource owners the check's resource use compares. The rebuild prunes with it, and the open and the self check read with it. It keeps an explicit work list and never recurses, so a cycle or a deep nesting cannot stop it. AC-1 to AC-3. Since spec 0020 it also hands back the glyph side (`glyphs`: one unit per Type 3 font and each dictionary it draws with, its streams the glyph procedures, `joined` false) and `outside` (every indirect object reached by a path that never passes through a Type 3 font's `/CharProcs` or `/Resources`). `outside` is computed from edges recorded during the loop, after it, never by visiting an object again: a second visit would mint fresh ids for dictionaries written in place and push deletions twice. A walk with a problem gives both empty. Spec 0020, AC-1, AC-2. Since spec 0021 each string place says what its string must read as (`StringText`: `language-tag` against `LANG_TAG`, `token` against `CID_TOKEN`, or `any`), and the walk fails a string outside it as a shape the format never gives that key, so a `/Registry` or `/Ordering` outside the token is refused, never deleted. `decodeTextString`, `readsAsLanguageTag`, `foldPlaceText`, `foldTicked` and `holdsTicked` live here too, so the scan, the rebuild and the check decode and compare a string one way (INV-1). Spec 0021, AC-1 to AC-4.
- `marked.ts` is the read only scan of a page's decoded drawing instructions (spec 0019, *Scan rules*): `readDrawing` answers whether a marked content property list holds a string that counts, which resource names the streams use, whether the streams show text (`showsText`, which the glyph rule reads, spec 0020), or `"unsure"`. `showsText` lives in the scan's `Semantics` and is copied by `copy()`, so a retry past a false `EI` restores it; a flag kept outside would stick from bytes read past one and refuse a bitmap font. It is spec 0001's one named exception to "one PDF parser": it edits nothing, computes no geometry, and nothing it answers changes what the rebuild keeps. Any doubt is `"unsure"`, which warns at open and fails the check, so a fault in it can add a warning or a refusal, never pass a file. Never read drawing instructions anywhere else. INV-4. Since spec 0021 its inline `/Lang` rule is `readsAsLanguageTag` from `allowlist.ts`, the catalog's rule too. One call gives inline images at most `INLINE_END_RETRIES` (16) new ends before the stream is `"unsure"`, because each retry reads the rest of the stream again and a crafted stream of false `EI`s would otherwise cost about an hour per megabyte. An inline image's `/CS` written as an `/I` or `/Indexed` array counts its base as a use when the base is a name. Spec 0021, AC-6, AC-7.
- `glyphs.ts` is the glyph rule (spec 0020). `judgeGlyphs` reads what every Type 3 font's glyph procedures draw, starting from a role walk's `glyphs` and following each name through `readDrawing`, and answers `"text"` when any of it shows text, `"shared"` when it names a form, picture or tiling pattern (or is a glyph procedure) that the walk's `outside` also holds, else `"clean"`; `"text"` outranks `"shared"`. `glyphRuleOf` is the run's seam default: a read walk from the pages, `"problem"` if that walk names one, else `judgeGlyphs`. One function decides for the open, the run and the check, so they never disagree (INV-3). It refuses and never edits a glyph, a resource or a content stream (INV-2). Sharing is by object identity, on drawings only, never by content (INV-4), and a glyph side drawing the scan cannot read is judged as the worst it could do (AC-4). Whether any text draws a glyph plays no part (INV-1).
- `find.ts` is detection's step (spec 0005): it reads each page through `walkCharacters`, hands each text block to `@/detect`, and turns every find into quads and a target, or blocks it with the reason the engine would refuse it for. It yields and checks for a cancel after each page read through the same `checkpoint` in `failure.ts` that a run uses (AC-11). This folder is the only importer of `@/detect` (INV-8).
- `device.ts` is the one drawing reader (spec 0006). `walkDrawing` runs a prepared page through a MuPDF callback `Device` with `Matrix.identity` and hands out what the page draws as plain data, in drawing order, with a `DrawState` saying what clip and group it sits under. `inspect.ts` and `trim.ts` both read pages through it, so they agree on what a clip or a group means. Never run a page through a `Device` anywhere else.
- `inspect.ts` reads each prepared page of the review copy at open (`inspectPages`): once through `device.ts`, once as ordinary mode structured text. It turns what it sees into closed page findings, a readable flag and the origins of concealed glyphs. Only the findings leave the engine. Spec 0006, *Page findings*. It also runs `marked.ts` over the drawing streams the open's role walk names for each page (its contents, and every form, tiling pattern and Type 3 glyph procedure it draws), and adds `marked-descriptions` where a description may be written into the page or a stream cannot be read to its end. Spec 0019, AC-9.
- `trim.ts` removes the text and drawn shapes outside each page's visible area (`trimToVisibleArea`), proves its text work on the page loaded afresh, and names a page whose picture reaches outside. Each copy is read on its own terms, never from the inspection, so a working copy decides exactly as the review copy did. Spec 0006, AC-14 to AC-16.

## Conventions

- A run never touches the review copy or `EngineSession.bytes`. `redactDocument` takes the clean bytes, never the review handle, and opens a working copy of its own that it destroys before returning. INV-1.
- The pipeline order in `redact.ts` is fixed: inventory, prepare, the glyph rule (`Pipeline.judgeGlyphs`, refusing with `unreadable-structure` on any answer but `"clean"` or a throw, before anything is removed), trim, validate targets, slant, images, record every page, the three passes page by page, rebuild (graft, `stripToAllowlist`, `pruneToRoles`, `sweepCarriers`), write, self check; on the check's `unused-colour-space` verdict alone, a checkpoint, the second write and the whole self check on its bytes. Each step's comment says why it sits where it does, so do not reorder them. Spec 0004, *State transitions*, as specs 0006, 0019 and 0020 (AC-6) amend it.
- The open's order in `open.ts` is fixed too: door, open, password, page cap, layers, prepare, the role walk (read only, from each page through `findPage` and `getInheritable`, never the page tree), inspect, the `no-readable-text` refusal, the empty clip refusal, the role walk's `unreadable-structure` refusal, the glyph rule's `unreadable-structure` refusal (`judgeGlyphs` on the same walk, a throw refused too), trim. Detection follows, on the trimmed page. Spec 0006, *State transitions*, as specs 0019 (AC-3) and 0020 (AC-5) amend it.
- Anything that changes what a page shows goes into `prepareDocument` in `prepare.ts`, which runs on the review copy at open and on every working copy. Never apply such a change to one copy alone, or detection and redaction read different pages. INV-9, AC-22.
- The trim follows the same rule: `trimToVisibleArea` runs right after `prepareDocument` wherever that runs, through the one function, so detection, target validation and the character record all read the same prepared and trimmed page. Spec 0006, INV-3, and spec 0004's INV-9 as spec 0006 rewords it.
- Inside the visible area, text is removed only on the removal band, a thin strip through the middle of each quad (the four cornered area that outlines a match). Never on a line box, a padded area or a raw quad, because MuPDF takes out every glyph whose full height box touches the area. The black box is drawn last, on the line box. Outside the visible area, the trim removes all of it (spec 0006). INV-11.
- The trim never decodes, blanks or removes a picture. One reaching past the visible area by more than `PICTURE_REACH_MIN` is kept whole and its page named `off-page-picture`, because MuPDF writes every image it blanks again as Flate (a 50 page cropped scan went past 800 MB). A run hands back its `TrimOutcome` for every page, and the worker's `trimAgrees` refuses the file with `unsupported` unless it matches the open's `off-page-content` and `off-page-picture`. Spec 0006, INV-6, INV-11, AC-18.
- The three passes in `passes.ts` write out all four `applyRedactions` arguments, defaults included, so a MuPDF upgrade cannot quietly change what is removed. After each pass the page must hold no `Redact` annotation, or the run fails. INV-5.
- A slanted target is refused with `slanted-text`, and an image that would be blanked too far with `redaction-overreach`, before anything is removed. Never cut an area into pieces to get round this: MuPDF judges covered line art one area at a time, so a mark that straddles a join would survive. AC-28, AC-29, INV-15.
- The engine never edits a content stream itself. What MuPDF cannot remove is refused, never patched, because a hand written edit would be a second PDF parser. INV-13. What MuPDF cannot remove and the engine cannot refuse is warned about instead: a description written inline in a page's drawing instructions stays, and the page gets `marked-descriptions` (spec 0019, AC-9).
- The output is rebuilt from allowlists, never cleaned by subtracting known keys: `PAGE_KEYS`, `CATALOG_KEYS`, `CARRIER_KEYS` and `WRITE_OPTIONS` in `rebuild.ts`, and `TRAILER_KEYS`, `ROLES` and `STRING_PLACES` in `allowlist.ts` for the trailer and every object below the pages. The write is never `incremental`, `encrypt` or `linearize`. Changing a list is a reviewed change with a failing fixture as its proof. INV-3, as spec 0019 amends it.
- The catalog keeps `/Lang` only when the source's is a string that reads as a language tag and holds no ticked item's text (`keepsLang` in `rebuild.ts`). Anything else is left out, with no refusal and nothing reported, since no page needs it to draw. The ticked texts are folded once per run (`foldTicked` in `redact.ts`), and that one list goes to `graftPages` and `checkOutput`, so the rebuild and the check never disagree. The folds are document text, held only for the run, as the character record is. Spec 0021, AC-1, AC-4, INV-1.
- `CARRIER_KEYS` is a backstop since spec 0019, because the prune deletes every carrier first as a key off every role's list. Never widen it key by key: a key the output must not keep is already off the lists, and one it must keep is a reviewed `ROLES` change with a failing fixture as its proof. Spec 0019, INV-6.
- The prune deletes keys and nothing else: a key off every role an object is reached under is deleted, a null at a dictionary key is deleted, and a null inside an array stays, since removing it would shift the positions after it. A listed key in a shape the format never gives it, or an object one of its roles keeps a key on and another drops, refuses the run with `unreadable-structure` before anything is written. A resource the format gives no drawing (an XObject neither image nor form, a pattern type neither 1 nor 2) is deleted from its resource dictionary, not refused. Spec 0019, AC-1 to AC-3, INV-2, INV-7.
- The second write (`rewriteOutput` in `rebuild.ts`) runs only on the check's `unused-colour-space` verdict, at most once. It opens the first bytes, calls nothing on that document but `asPDF` and `saveToBuffer(WRITE_OPTIONS)`, and never deletes an entry itself: which colour spaces MuPDF can load, and what its filter keeps, is MuPDF's call (INV-13). The new bytes face the whole check with no second chance, then their `drawnShape` must match the first bytes' (next line), or the run fails with `unsupported`. Never run it on every file: it costs up to a second first write (54% of the 10,000 form run). Spec 0019, AC-15, INV-8.
- The drawn shape (`drawnShape` in `self-check.ts`) is, for every role `ROLES` lets be a stream (`STREAM_ROLES`, derived from `ROLES`, never written by hand), the sorted stored lengths of every object the walk reaches in that role, so a second write that dropped or changed a form, picture, font file, pattern, shading or function fails. Every list must be equal, except for the roles in `BELOW_COLOUR_ROLES` (only `colour-profile`, the entry the second write exists to drop), where the second may lose whole objects, matched one for one, and never change one. A stream role added to `ROLES` joins the shape by itself. Spec 0021, AC-8, INV-5.
- Every MuPDF object (document, page, structured text, buffer) is destroyed in a `finally` on every path out, because garbage collection never reclaims MuPDF's native memory. The destroy order in `redact.ts` holds a run's peak at about four copies of the document, the second write included: the rebuilt document is gone and the first bytes are let go before it opens them again (spec 0019, AC-15).
- A failure is an `EngineFailure` carrying one kind and nothing else. A throw while a pass runs is `unsupported`. A throw while checking the output is `redaction-incomplete`, because a check that cannot finish vouches for nothing. `RunCancelled` is not a failure, and the worker never posts it.
- Spec 0006 added two kinds, both refusals that say no file was made. `no-readable-text` refuses at open a document with no page it can read, before the trim and detection, so no session and no run can exist (AC-10). `edge-text` names a trim whose proof failed only on lines that cross a page's visible edge; any other proof failure is `unsupported` (AC-16). Text drawn under a clip that holds no area is refused at open as `unsupported`, after the `no-readable-text` check, because MuPDF's `sanitize` write drops it and every run on the file would fail (AC-11). None says which page.
- A character MuPDF cannot place refuses the open with `unsupported`, and every run the same way, inside the trim (`planTrim` in `trim.ts`), so the visitor never reviews and ticks a file every run would fail. A line box that is inverted or not finite is only a sign (`isPlacedBox`): `holdsUnplaced` then reads that page's characters in both unclipped modes and refuses when one that is not whitespace has a centre that is not finite, exactly what the self check's outside rule fails. A space MuPDF cannot place is skipped in both, so that page still opens, and only a page with such a line pays for the read. Spec 0006's Follow-up, pinned by `trim-unplaced.pdf`, in the gate's `OPEN_NOW`.
- Spec 0019 added `unreadable-structure`, appended last to `ENGINE_ERROR_KINDS`: the role walk's refusal, at open after the empty clip refusal and in a run before anything is written. It names no page. AC-3. Spec 0020 gives it a second cause, the glyph rule, at open and in a run before any pass, with the same words, so a count of it cannot tell the two apart.
- The inventory reports `attachments` for any embedded file stream (`/Type /EmbeddedFile`) or file specification holding `/EF` anywhere in the source, an orphan nothing reaches included, on purpose, and the self check fails any output still holding one. Spec 0019, AC-8.
- A page's findings are a closed set, `PAGE_FINDINGS` in `src/worker/protocol.ts`, kept in the order the lines are shown. `inspect.ts` gives each page zero or more, and the open adds the trim's two (`off-page-content`, `off-page-picture`) through `withTrim`. Inspection keeps nothing past the open but findings, readable flags and concealed glyph origins, all dropped with the review document. Spec 0006, INV-1, INV-8.
- Every MuPDF object a device callback receives with a kept reference is destroyed before the callback returns, and nothing a callback receives is held past it. A callback never throws: it catches, remembers the first failure, and `walkDrawing` throws that once `page.run` has returned, because a throw would unwind through MuPDF's C frames without their cleanup. Which objects are destroyed and which are not is under *MuPDF quirks*. Spec 0006, INV-10.
- The engine only yields and asks. At each checkpoint a run yields a macrotask (`setTimeout` with 0, so a waiting `cancel` message is delivered first), then reads `isCancelled`. The worker owns the run queue, the cancelled set and replacement. AC-17, AC-18, AC-23.
- `PDF_HEADER_WINDOW`, the geometry values in `geometry.ts` and the self check's values in `characters.ts` are engine constants, never config. They are rules about the file format and about geometry, not caps on the visitor, and an environment variable would let a typo switch a check off. They are the deliberate exception to "every cap comes from `src/config`", and each comment says so.
- The page reading's thresholds in `inspect.ts` (`READING_GRID`, `PICTURE_MIN_SHARE`, `STAMP_MAX_CHARS` and the rest) and `PICTURE_REACH_MIN` in `trim.ts` take the same exception. They are rules about pages, not caps on the visitor, and an environment variable could switch a warning off. Their measured values are in spec 0006's *Constants* and `rationale.md`. Spec 0006, INV-7. `MACHINE_READ_RUN` and `COPY_REACH_RATIO` joined them with spec 0008, whose *Decision* and `rationale.md` hold their reasons. `ROLES`, `STRING_PLACES`, `TRAILER_KEYS` and `LANG_TAG` joined them with spec 0019: rules about the file format, not caps on the visitor (INV-5). Spec 0021 moved `LANG_TAG` into `allowlist.ts` and added `CID_TOKEN` and `ADOBE_COLLECTIONS` beside it, `INLINE_END_RETRIES` in `marked.ts` and `BELOW_COLOUR_ROLES` in `self-check.ts`, on the same terms (its INV-6).
- The find step reads a glyph off its line (smaller and raised or lowered, or a code point in `SUPERSCRIPT_CODE_POINTS`) as a boundary: a short glued stretch of them leaves the text the detectors read as one synthetic space (`source` -1, not in `joins`), and a target's quads part round it, so a footnote marker never glues to a value and a ticked row never covers one. Its four `OFF_LINE_*` constants in `characters.ts` take the page reading's exception, measured in spec 0014's `rationale.md`. Only `detect-markers.pdf` may hold an off line glyph; `detection.test.ts` reads every other fixture to hold that, so a new fixture with a superscript needs its own decision. Spec 0014, AC-4 to AC-7.
- A machine read run and the readable count are two rules, never merged. `runStep` decides what counts toward a run (only `\p{L}` and `\p{N}`, a combining mark carries one), while `isReadable` still decides the readable count, so punctuation stays under the stamp cap. `machineReadRun` is searched only after a picture fails the coverage test and the page draws at least `MACHINE_READ_RUN` invisible glyphs, so a born digital page pays nothing. Spec 0008, AC-12, AC-14.
- Only visible lines of words count toward a picture's coverage. `coverageLines` keeps a line of the ordinary read only when it holds a letter or number (`runStep`'s `"counts"`), every readable character on it has a drawn glyph at its origin, and none has an invisible one there, so an OCR layer, a line of marks and text the page never draws count for nothing. Machine read text clears a picture only through `machineReadRun`, dense or sparse. Never let a hidden line back into the coverage boxes, or a photo pasted onto a dense OCR scan is cleared by the scan's layer. The invisible glyphs and drawn glyph origins (`glyphOrigins`) are built once, only on a page with a picture, and shared by both rules, so a page with no picture pays nothing. [Spec 0010](../../docs/specs/0010-dense-text-layers-over-pictures/index.md), AC-1, AC-2, AC-10.
- Two extraction settings, never mixed. `EXTRACTION_OPTIONS` (MuPDF's defaults, which clip to the page) serves detection and target validation. `CHECK_EXTRACTION_OPTIONS` (the same plus `clip=no`) serves the character record and the self check. Never add `dehyphenate`, `collect-styles`, `segment`, `clip` or `accurate-bboxes` to the first: each changes which characters exist or where they sit.
- Detection and redaction ask the same checks. `unsoundTargetsIn`, `slantedTargets` and `imageReachVerdicts` in `targets.ts` each answer per target; `validateTargets` composes them in its fixed order, and `find.ts` asks them per match. Never write a second copy of a check in `find.ts`, or a match could be tickable and then refused. Spec 0005, INV-3.
- Beside the per block text the detectors read, the find step builds one whole page text for the custom terms (`TermInput` for `findTerms` in `@/detect`): the blocks joined by synthetic spaces, with `breaks` and `lineBreaks` recorded as `pageText` writes them, so a term crosses line and block breaks and the line end hyphen readings apply. Term places take the same `candidate`, checks and replacement text pass as detector places, and a term's hidden row yields only to an ordinary row of the same term. Each readable page is read once per open (detection and the kept list together) and once per review search batch, never once per term. A run counts `removedByTerm` after the self check, as it counts `removedByType`. Spec 0017, AC-9, INV-6, INV-8.
- The one piece of document text that outlives a page's read is the carried tail (`Carry` in `find.ts`): from each readable page, at most the longest searched term's length in characters that are not separators, in both extraction modes, held while the next page is matched and dropped after. Nothing carries past a page that is not readable, and only one page: a match across three pages is a recorded miss. A match across the break lists as two `page-break` parts; the first is checked on its own page, loaded again alone once the next one is closed, and lists after that page's ordinary rows and before its hidden ones. Spec 0005's one page rule, as spec 0017 amends it (INV-12, AC-33).
- `walkCharacters` in `characters.ts` is the one character reader for detection, target validation, the record and the self check, and it returns whole code points. Nothing downstream of it indexes text by UTF-16 unit. Spec 0005, INV-12.
- The character record holds document text (code points and positions) for the length of a run. It is never logged, never crosses the boundary, and is dropped when the run returns or fails.

## The self check

- `self-check.ts` reopens the written output from the exact bytes that will cross, and nothing is returned unless all three parts pass. Structure: only allowlisted keys, no carrier keys, no `/JS`, one revision, the source's page count. Characters: every page equals the source's characters less the ticked ones, in both extraction modes, with none centred under a box. Pixels: every image under a target is blank there. INV-2, AC-13.
- Compare, never sample. Every page is recorded before any page is redacted, and pages with no target are compared too, so damage to a shared resource, or text the write drops, is caught.
- Spec 0019 adds to the structure part (`structureIsClean`), holding every rule the prune applies on the written bytes whether or not the prune ran (INV-3): the trailer holds only `TRAILER_KEYS`; a `"read"` walk from the catalog meets no key off its role's list, no value outside its shape and no string outside `STRING_PLACES` or outside what its place reads as (spec 0021, AC-3); every object satisfies every role it is reached in, so two emptied dictionaries the write merged still pass; every object in the file is reached; no embedded file stream, file specification or `/EF` is anywhere, reached or not; and every resource entry is named by a drawing that draws with its dictionary (*Resource use*, through `marked.ts`). Any of these is `redaction-incomplete`. AC-5.
- The structure part answers a `StructureVerdict`, ranked leak, then `unreadable` (a drawing stream the scan cannot read to its end, `unsupported` unless a leak outranks it), then `unused-colour-space`, then clean. `checkOutput` with `mayRewrite` set answers `"rewrite"` for `unused-colour-space` before the page loop, inside its one open of the bytes, so the usual path opens and walks the output once; with it clear, the same verdict is `redaction-incomplete`. Never split `checkOutput` in two, which would open the first bytes twice. AC-5, AC-15.
- Spec 0021 adds the string place check (`tickedAtStringPlace`) inside `checkOutput`, so the order there is: the structure part, then this check, then the `"rewrite"` answer, then the page loop. It holds the catalog's `/Lang`, and every `/Registry` and `/Ordering` string in any dictionary, reached or not, against the run's folded ticked texts. A hit is `redaction-incomplete`, so it outranks an unreadable stream and an unused colour space, never leads to a second write, and runs again on the second write's bytes. It sits in `checkOutput`, never behind the `checkStructure` seam, so a swapped structure check still faces it. Adobe's own values, whole (`ADOBE_COLLECTIONS`), are never compared, so ticking `Adobe` or `ID` refuses no file with such a font; a string that cannot be decoded counts as a hit. Spec 0021, AC-4, INV-3.
- Spec 0020 adds text below a glyph to the structure part: `structureIsClean` calls `judgeGlyphs` on the walk it already makes, after resource use's `"leak"` return and before `return use`, and answers `"leak"` on `"text"` only, so it outranks `unreadable` and `unused-colour-space` and never leads to a second write. It never judges a shared drawing on the written bytes: after the passes the page names MuPDF's redacted copy and the glyph the original, and a write that merges two identical pictures would make a clean file look shared. The refusals at open and before the passes hold that part. AC-7.
- The kind follows AC-25's order, a leak first: `redaction-incomplete`, then `replacement-text`, then `redaction-overreach`. On a run with nothing ticked, any difference is `unsupported`.
- Spec 0006 adds one rule that is `redaction-incomplete` whatever is ticked: no character centred outside a page's visible area survives, in either extraction mode. The record is taken after the trim, so a trimmed character is never expected back, and a trim that silently did nothing is caught here. The trim changes no pixel, so there is no pixel rule for it. AC-17.

## MuPDF quirks

Measured on MuPDF 1.28.1. The ones the design rests on are pinned by a test, so an upgrade that changes them fails a test rather than quietly widening what a pass can reach.

- MuPDF picks its handler by sniffing content, so it opens a PNG as a one page document even when told `application/pdf`. `door.ts` looks for `%PDF-` in the first 1024 bytes before the engine loads, and never reads the file name or declared type. AC-1, INV-4.
- It acts on each redaction area's upright bounds, not the area itself. Covered line art is judged over the bounds, and pixels are blanked over the bounds in each image's own pixel grid, whole pixels at a time. That is why the slant and image reach checks exist. Pinned by `bounds-pin.pdf` in `tests/unit/redaction-matrix.test.ts`.
- Default extraction clips to the page. The content filter, which the text pass and the `sanitize` write both run, rewrites a text object positioned with `Td` that later shows a line with `'` or `"`, so those lines jump, often off the page, and a match on them is kept rather than removed. That is why the check reads with `clip=no`. Pinned by `next-line-0.pdf` to `next-line-4.pdf`.
- A size change (`Tf`) or horizontal scaling change (`Tz`) inside one text object, between removed glyphs and the next kept one, moves the text after them. A combining mark drawn at zero width on a match's last letter survives the band. The self check refuses both with `redaction-incomplete`. They are honest limits, not bugs to patch (`reach.pdf`, `combining.pdf`).
- The log is silenced with a callback that discards every line (`silenceEngineLog` in `load.ts`), installed as the engine loads, never with `setLog(null)`. `null` means no callback, and what MuPDF does then is its own choice. AC-24.
- `page.getAnnotations()` answers from a list MuPDF.js keeps on its side, which a redaction does not refresh. Read `/Annots` from the page object instead, as `passes.ts` does.
- `asUint8Array()` on a MuPDF buffer is a view into the WebAssembly heap. Copy it with `slice()` before the buffer is destroyed, as `takeOutput` in `redact.ts` does.
- A missing key comes back as one shared `Null` object, and calling `get` on it throws. Look keys up through `hasKey` and the other readers in `objects.ts`.
- `graftPage` is not relied on to carry a page's `/Group`, so `rebuild.ts` grafts it across explicitly.
- MuPDF.js 1.28.1's structured text walker builds each character with `String.fromCharCode`, so a code point above U+FFFF comes back as its low 16 bits. `walkCharacters` puts back each such line's code points from `asJSON()`, and fails closed (`unsupported`, or `redaction-incomplete` in the self check) when the counts or the low bits disagree. Pinned in `tests/unit/characters.test.ts`, so a release that fixes it fails the pin and the repair can go. Spec 0005, AC-26.
- `search()` stops at 500 quads and drops the rest without saying so. That is why detection walks characters, and why lint bans `search()` in this folder and in `src/detect`. Spec 0005, AC-25.
- A stream resolved through MuPDF.js, then written with `garbage=deduplicate` where the write merges an identical object the stream's dictionary points to, leaves as a dictionary with no data, in a grafted document and in one opened from bytes alike, so a picture or a figure loses its drawing. That is why nothing in this folder calls `.resolve()`: read and edit every object through its reference (`get`, `forEach`, `delete`, `put`, `isStream`, `isDictionary`). Lint bans a call to any member named `resolve` here, `.resolve()` and `["resolve"]()` alike, `Promise.resolve()` included. A template literal key, a computed key and a destructured `resolve` all pass the ban, so review catches those (the comment above `noResolve` in `eslint.config.mjs`). Pinned in `tests/unit/redaction-kept.test.ts` (*MuPDF's empty stream after a resolve*, on `shared-pictures.pdf`), so a release that fixes it fails the pin and the ban can be revisited. Spec 0019, AC-16, INV-9.
- `sanitize` copies a `/ColorSpace` entry into the new resources when a drawing names it, then, when the space fails to load (an unreadable `/ICCBased` profile, a `/CalRGB` or `/CalGray` with a zero white point), draws a device colour instead, so nothing names the entry; a second pass of the same filter drops it. That is the second write's one trigger. The colour fixtures' runs with `rewrite` returning its input fail with `redaction-incomplete`, so a release that fixes it shows there and the second write can go. Spec 0019, AC-15.
- MuPDF.js exposes no marked content (no callback hands out a `BDC` property list, and no filter drops one), and `sanitize` keeps an inline `/Alt` and an `/ActualText` around no text. That is why `marked-descriptions` warns rather than removes. Pinned by `marked-descriptions.pdf` in `tests/unit/marked.test.ts`, so a release that changes either fails the pin and the warning is revisited. Spec 0019, AC-10.
- In a device callback, MuPDF.js 1.28.1 wraps `Path`, `Text`, `StrokeState` and `ColorSpace` with a reference it keeps, and an `Image` arrives with one too, so `device.ts` destroys each. A `Shade` arrives with no reference, yet still registered for collection, and a collected wrapper frees a shading MuPDF is still using (measured: the next page run crashes). So a `Shade` is disowned, never destroyed. The text walker's `Font` is a wrapper MuPDF.js keeps and reuses itself, so it is left alone. Pinned in `tests/unit/device.test.ts`. Spec 0006, INV-10.
- `disown` in `device.ts` takes a `Shade` out of MuPDF.js's collection registry through the class's private `_finalizer`, which is not public API. `tests/unit/device.test.ts` reads the same field directly, so an upgrade that renames or drops it fails that pin instead of letting `disown` quietly do nothing.
- A page whose crop box differs from its media box is run inside a clip to the crop box, which MuPDF opens before anything is drawn. `isPageClip` in `device.ts` leaves that clip out of "the clip in force", or every picture would be cut to the visible area and the trim could never see a cropped scan's margins. Pinned in `tests/unit/trim.test.ts` (*MuPDF's own crop clip*). Spec 0006, AC-14, AC-15.
- The trim rests on four more pins in `tests/unit/trim.test.ts`: the default read drops characters outside the crop box; a Redact area outside the crop box, below the media box or left of the page removes every glyph there, a glyph straddling the edge included; glyphs ending 0 and 0.5 pt inside each edge survive in Helvetica, Courier, Times and Carlito; and a line's box is the union of its characters' quads. A cropped OCR scan written the way Tesseract writes it opens named, not refused with `edge-text` (`trim-ocr.pdf`). If a foundation pin fails, stop and take the measurement to `/architect`.
- `trim-rotated.pdf` pins the trim on a `/Rotate` page (*a turned and cropped page* in `trim.test.ts`): three pages turned 90, 180 and 270 degrees, cropped away from the origin on every side, read the visible area and the media box in the same turned page space, so `planTrim`'s strips, the media box fallback for a shading with no bounds and the annotation quad points agree through the open, a run and its self check. Its third page, the shaded one, is never ticked, there or in the gate's `NEEDLES`: a shading under a ticked item reads as a picture to the pixel part and refuses the run, on main too (the scope's Deferred). Spec 0006's Follow-up.
- MuPDF.js 1.28.1 gives a character it cannot place (text drawn under stacked transforms past the float range) a quad of `NaN` or infinity, on a line whose box is MuPDF's empty box `[0, 0, -1, -1]`, never a box that is not finite, because its box union skips such quads. That is why `isPlacedBox` takes an inverted box as a sign too. Pinned in `trim.test.ts` (*a character MuPDF cannot place*) on `trim-unplaced.pdf`.
- The trim's pass rewrites the page it touches and drops every `0 0 Td`, so a text object placed by `cm` keeps no positioning operator, and MuPDF's text pass then carries the advance of the glyphs it removed at the end of one text object across `ET` and `BT` into the next, moving that text. The self check refuses the run with `redaction-incomplete`, so it fails closed: a recorded limit, and why a matplotlib chart whose x axis label reaches past the page refuses a run that ticks its title. Pinned by `trim-carry.pdf` in Helvetica (*MuPDF's carry into the next text object after the trim* in `trim.test.ts`). An upgrade that fixes it fails the pin: take the chart back to spec 0020's Follow-up and feature 30 then, never loosen the pin.
- MuPDF 1.28.1 does not draw an inline picture whose indexed `/CS` names a resource as its base, and a run's write keeps neither the picture nor the entry, so the scan's reading of that base (spec 0021, AC-7) reaches no output today. Pinned in `redaction-kept.test.ts` (*MuPDF and an inline picture over a named indexed base*), so a release that starts drawing it shows the rule now matters.
- An inline picture whose indexed colour space is written inline (`/CS [/I /RGB 3 <...>]` or `[/Indexed /DeviceRGB 3 <...>]`) draws in the source, but MuPDF 1.28.1's write turns its `/CS` into an empty name, so it vanishes from the cleaned copy with the check passing, on main too. It loses ink and keeps nothing, so it fails safe for privacy. No test pins it yet: it is feature 30's open item, owed to `/debug` then `/architect` (spec 0021's *Follow-up*).
- The reading rests on pins in `tests/unit/reading.test.ts`: invisible text arrives through `ignoreText`, image placements through `fillImage`'s transform, an unmapped glyph reads as U+FFFD in ordinary mode, a glyph mapped to two code points is two calls at one origin, and `sanitize` drops text drawn under a clip that holds no area (`read-empty-clip-0.pdf` to `read-empty-clip-3.pdf`).
- Spec 0010's coverage rule rests on two more pins in `reading.test.ts`: replacement text (`/ActualText`) longer than its glyphs puts its extra characters at no glyph's origin, so such a line counts for nothing, and each character of vertical writing (`/Identity-V`) reads as a line of its own, so a dense vertical layer forms no run and its scan stays named, a recorded limit. AC-6, AC-7.

- The seam: each function ending in `With` (`openDocumentWith`, `redactDocumentWith`) takes the loaded MuPDF module, so Vitest runs the real engine in Node. The worker calls the plain versions, which load it themselves. Never add a setter on `loadEngine` instead, because the walled module holds no mutable hook.
- `Pipeline` in `redact.ts` is a frozen parameter whose default is `PIPELINE`. A test swaps the text pass, the padded pass, the removal area or the carrier sweep to prove each part of the self check fires (`tests/unit/redaction-check.test.ts`). ## Fixtures

- `tests/fixtures/*.pdf` are written by `node scripts/make-fixture.mjs`, object by object, with `scripts/lib/`: `pdf-writer.mjs` serialises, `redaction-fixtures.mjs` holds the matrix, `detection-fixtures.mjs` the `detect-*.pdf` set, `reading-fixtures.mjs` the `read-*.pdf` and `trim-*.pdf` sets, `terms-fixtures.mjs` `terms.pdf` and `terms-dense.pdf`, `kept-fixtures.mjs` the `kept-*.pdf`, `colour-*.pdf` and `shared-*.pdf` sets and `marked-descriptions.pdf` (spec 0019), `glyph-fixtures.mjs` the `glyph-*.pdf` set (spec 0020; a `null` in `writePdf`'s objects leaves that number free, for a recipe that skips one), `pdf-encrypt.mjs` encrypts the `rc4`, `aes-128` and `aes-256` owner password files with `node:crypto`, and `truetype.mjs` reads Carlito's metrics. None is made by MuPDF, so an engine bug cannot write a fixture that hides itself.
- Change the script, never a PDF by hand. Run it and commit what changes. With no script change, a run leaves `git status tests/fixtures` clean.
- `tests/unit/fixtures.test.ts` holds that in `pnpm test`: it runs the script from an empty temporary folder and compares what it writes with `tests/fixtures`, by name and byte for byte. So a fixture's code changed with no rerun, a hand edit, and a stray or missing file all fail it. The script must keep writing the same bytes on every run (fixed dates and IDs, seeded keys, salts and IVs in `pdf-encrypt.mjs`), so a new fixture never takes randomness or the clock. Feature 27.
- Fonts: MuPDF's built in Helvetica (a 1.37 em quad) and Courier (1.25 em), and Carlito embedded (1.0 em, metric compatible with Calibri) from `scripts/fonts/`, with its SIL Open Font License beside it. Microsoft's fonts cannot ship in this public AGPL repository.
- Write each needle in the same case as the page, because the target helper searches for it.
- Never commit a real document, not even for a corpus measurement: the repository is public.
- The heavy 50 page document the browser cancel test needs is built inside `tests/e2e/cancel.spec.ts`, not committed.
